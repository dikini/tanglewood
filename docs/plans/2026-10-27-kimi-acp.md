# Kimi ACP Implementation Plan

> **Execution:** Root orchestrates this bounded follow-up. Use the requested GPT-6.1 Terra/max developer and the same independent Sol6.1/xhigh reviewer after the planning review; at most four review/development cycles. Do not start or resume the separate MVP goal.

**Goal:** Offer installed Kimi Code CLI through the existing quiet conversation experience, including server-discovered model/thinking controls, safe session switching, streaming, cancellation, approvals and the existing owner MCP bridge.

**Architecture:** Add one small concrete backend boundary and a Kimi ACP worker. Share presentation and source snapshots; preserve each provider's real protocol and control semantics. Application commands, ECS ownership, storage and MCP authorization remain the existing single-writer path.

**Tech stack:** One Rust package; existing Serde/JSON, worker channels, Linux process primitives and egui. Target Kimi Code CLI 2.2.0 with ACP protocol 1. No new runtime or generic provider framework.

## Scope and evidence

Read `AGENTS.md`, `docs/plan/tanglewood-mvp.md`, `docs/design-system/README.md`, `docs/plans/2026-10-26-approved-egui-shell.md` and the approved HTML reference before changing the UI. The implementation must retain the quiet header/sidebar, shared Markdown typography, compact tool activity, accessible controls, adaptive composer and reachable context pullout.

The initial slice includes Kimi connect/disconnect, session list/new/load, text and explicit text-snapshot context, live assistant Markdown, plan/tool activity, Stop, native permission choices and model/thinking/mode selectors. Session selection must survive reconnect and recover drafts. History stays in Kimi's storage; no transcript migration or new vault schema is required.

Capability facts were checked against [Kimi's ACP reference](https://www.kimi.com/code/docs/en/kimi-code-cli/reference/kimi-acp.html) and local metadata-only probes on 2026-10-27. The installed server reports protocol 1, load/list/resume/close/delete/fork, and stdio/HTTP/SSE MCP forwarding. `session/load` replays updates before its response. The initial implementation uses stdio, new/list/load/close and config options; fork and destructive session management UI remain deferred. The live harness may delete only the session it created for cleanup.

Local `/tmp/tanglewood-kimi-acp-initialize.json` and `/tmp/tanglewood-kimi-selectors.json` are evaluation evidence, not runtime dependencies. The observed model list has nine configured entries; selected K2.8 Preview exposes Thinking Low/High/Max and Default/Plan/Auto/YOLO modes. These values must not become a fixed catalog. The metadata probe created, closed and deleted an empty temporary session and ran no paid prompt.

Use [ACP session config options](https://agentclientprotocol.com/protocol/v1/session-config-options): options and values retain their IDs, names, descriptions, grouping and server order. A successful set response or config update replaces the complete option snapshot, including dependent choices. Categories are placement hints, not dispatch keys. Missing/unknown categories remain usable; unknown types are ignored. Support flat/grouped selects initially and do not advertise optional boolean support.

Excluded: REST/WebSocket server integration, Android, sync, multiagent runtime, Kimi login/logout UI, image/audio inputs, terminal/filesystem reverse-RPC hosting, elicitation forms, skill catalog parity, goals, fabricated projects, and rename/archive aliases. Existing Codex functionality remains available with its present behavior.

## Fixed contracts

### 1. Small backend boundary

Create `src/conversation.rs` with concrete types along these lines; keep public Codex exports source-compatible where common display structs move:

```rust
pub enum Backend { Codex, Kimi }
pub struct ConversationKey {
    pub backend: Backend,
    pub workspace: PathBuf, // canonical local context directory
    pub session: String,
}
pub enum Adapter { Codex(CodexAdapter), Kimi(KimiAdapter) }
pub enum Request { Codex(CodexRequest), Kimi(KimiRequest) }
pub enum Event { Codex(CodexEvent), Kimi(KimiEvent) }
```

Compile-time feature gates apply to unavailable variants. `try_send` rejects a request for another backend. Do not make Kimi imitate `CodexRequest`, `TurnControls` or Codex project APIs. Common attachment/plan/tool-display data can live here and be re-exported from `codex.rs`; goals, skills and Codex approval decisions remain provider-specific. Preserve existing adapter tests instead of rewriting them around a new generic transport.

Use optional features `conversation = ["mcp"]`, `codex = ["conversation"]`, `kimi = ["conversation"]`. Gate shared UI/context/Markdown code on Linux plus either provider; Kimi-only builds must not require Codex protocol types. Keep the existing module filenames unless a necessary extraction makes ownership clearer.

One `ConversationPanel` renders both backends. Provider-specific state lives in a small enum/owned state record; common transcript/composer/context rendering stays shared. Preserve Codex controls verbatim in its branch. Backend switching is an explicit selector in the conversation header, with the model/thinking choices beside the existing composer controls. Do not build a second conversation screen or duplicate the document renderer.

### 2. Identity, switching and draft ownership

Every event is attributed to its backend, canonical context directory and connection generation. Session/turn/message/tool identifiers are scoped within that identity; do not key shared caches or widget IDs by a naked session string. Drafts include prompt, attachments, selected skills where applicable, and unsubmitted provider options. Never carry Codex skills, access profile, goal or network choice into Kimi.

Allow only one foreground agent child in this panel. This UI lifecycle limit does not limit the MCP owner to one agent or client: independent agents and bridge processes may connect concurrently to the same owner. Disable backend/session switching during a prompt, permission request, config mutation or pending open. An idle backend switch parks local state, requests teardown, and activates the destination only after the previous child is killed/reaped. Retain local drafts and previews; a stale event from a previous connection cannot mutate the new panel.

For Kimi list, send the canonical `cwd` filter, bound pagination and independently reject rows for another directory. Only listed IDs for that workspace and IDs returned by this connection's successful new request can be loaded. A CLI resume argument must pass the same membership check; opening arbitrary IDs is not authorized by possession of a string. No periodic session polling; refresh on connection, explicit refresh and relevant acknowledged actions.

Use `session/load` for UI reopen because its history is needed. Buffer replay under the pending target identity before the response; it must not append into the old transcript, clear its draft, or be treated as live work/approval. On successful response, atomically commit the new transcript/config snapshot and restore that target's draft. On failure or disconnect preserve the old state and show the error. Bound replay with the same transcript budget; never display a silently incomplete history as complete. See [ACP session setup](https://agentclientprotocol.com/protocol/v1/session-setup) and [session listing](https://agentclientprotocol.com/protocol/v1/session-list).

Kimi `ThreadRef` uses `provider: "kimi"`, its real session ID and `project_id: None`. Codex retains its real project binding. Research open/capture resolves the complete provider identity against the corresponding workspace's confirmed list; it never opens a same-string ID from the wrong backend. Do not create fake Kimi project metadata or repurpose `CodexProjectBinding`.

### 3. Kimi session and configuration state machine

`KimiConfig` carries executable, canonical context directory, bridge path/socket and optional requested resume ID. Spawn `kimi acp` without `-y`, `--auto`, or a forced permissive mode; perform initialize before session requests. Check the installed agent name/version and negotiated protocol; unsupported versions fail with an actionable message. Existing CLI authentication is used; auth-required errors tell the user to log in with Kimi outside the app, preserving all drafts. Never read/copy tokens or alter global configuration.

New/load includes the same `tanglewood-mcp --socket <owner>` stdio server definition. Do not inject a second vault runtime. Provide bounded text guidance/context telling Kimi to use the owner tools for notes/research and to treat supplied source excerpts as data; guidance is not an enforcement boundary.

Store confirmed config separately from pending user intent. Kimi model and thought selectors render from the active session's latest option snapshot. The model control dispatches the option ID with category `model`; thought placement uses `thought_level`, including actual ID `thinking`. Modes use their own reported option and descriptions; if configOptions exists, do not display a duplicate legacy modes selector.

Apply changes in order: set model, await the returned whole snapshot, then validate any requested thinking value against the new snapshot and set it only if still offered. Re-render changed or absent reasoning options immediately. A failed request retains confirmed values; a late response applies only to its session/generation and active operation. Serialize config mutations and disable Send while one is pending. Never show an optimistic model as confirmed, submit unsupported effort values, substitute Codex effort names, or assume a reasoning choice survives a model change. No model turn is submitted by changing options.

A Kimi prompt owns one local operation/turn token. Its JSON-RPC response completes the prompt; session updates stream before that. Aggregate text chunks using real message IDs when supplied and bounded local role/message sequencing otherwise; user replay, assistant text, thinking and tool events must not merge into one message. Show agent text in the shared renderer and tools/plan in existing compact presentation. Do not expose private thinking as ordinary assistant text; unsupported content has a small honest fallback. Unknown notifications are ignored safely; unknown reverse requests receive a protocol error, never an implicit grant.

Keep a submission shadow of the exact prompt and attachments until a terminal successful prompt response. Queue acceptance is not remote acceptance. On rejection, timeout or disconnect retain/recover the submitted text and context, mark uncertain submission where appropriate, and require explicit user action before retry. Late config/prompt responses cannot clear a newer draft. Prevent duplicate local user messages when replay confirms an earlier submission.

### 4. Permissions, cancellation and process lifetime

Kimi permission UI displays bounded tool details and the exact offered option labels/IDs; return only a currently pending offered option ID, or `outcome: { outcome: "cancelled" }`. Keep Kimi decisions separate from `ApprovalDecision`. Scope request IDs to connection/session/prompt, reject stale/double answers, and clear them on terminal completion/teardown. On Stop, respond cancelled to outstanding permission requests, send `session/cancel`, and wait for the original prompt's terminal response before declaring the turn stopped. See [ACP tool permissions](https://agentclientprotocol.com/protocol/v1/tool-calls) and [cancellation](https://agentclientprotocol.com/protocol/v1/cancellation).

Do not advertise filesystem, terminal, elicitation or other client capabilities that are not implemented. This does not sandbox Kimi's own tools: Kimi runs with the user's ordinary process privileges. Its Default/Plan/Auto/YOLO descriptions come from ACP; no mapping to Codex Ask/Auto-review/No prompts/Full access is valid. Do not expose Codex's network toggle for Kimi or claim network isolation. The connection/settings help must state this material difference without adding permanent debug text to the transcript.

The existing **Allow agents to update notes and research** setting controls the owner MCP policy for either provider. Inspect current capabilities and recheck policy on every command exactly as today; disabling it must revoke mutations on an already connected Kimi session. Protocol approval is separate from command authorization and does not bypass revisions or durable acknowledgements. Concurrent MCP clients share this one owner, with isolated per-client request/reply routing even when request IDs overlap. Competing mutations still pass current revision checks; successful external mutations receive the matching durable acknowledgement. A client disconnect or panel agent teardown must not stop the owner, another client, or its pending reply. Live write revocation applies to every connected client at dispatch, without reconnecting. Keep the existing single-writer and domain policy contracts; no multi-agent orchestration is introduced.

Research snapshots/citations, discussion capture and saved findings remain shared. Kimi prepared research uses explicit source instructions and a draft preview that explains that Kimi's CLI controls tool/network access. It must not reuse Codex wording promising a network-disabled/sandboxed grounded turn. Its native Plan option follows the reported no-tool semantics, rather than silently emulating Codex Research/Goal modes. Preserve Codex's existing grounded/external behavior.

Reuse the proven Codex process-lifecycle pattern: I/O stays off the UI thread, bounded nonblocking channels, prompt/line/event/output/approval limits, stop-aware deadlines, bounded stderr diagnostics and owned process-group kill/reap. Preserve at least the existing limits: 16 UI requests/pending RPCs/approvals, 128 events/4 MiB event bytes, 256 KiB prompt plus context, 1 MiB JSONL frames, 2 MiB displayed/cached conversation data and 256 rows/messages. Config/list/replay data also count toward explicit bounds. Disconnect and window close retain the adapter until teardown is reported; editor rendering/autosave remain usable. Extract private low-level process helpers only if needed; do not refactor Codex's protocol state machine as incidental cleanup.

## Validation and stopping rule

During development root schedules the smallest relevant checks, for example `cargo test --lib --features kimi kimi::tests` and the affected existing UI scenarios under `gui,codex,kimi`. No Cargo run is needed for this plan. Do not run competing Cargo jobs in the shared target directory.

At the stable integration checkpoint root runs once:

```sh
cargo fmt --check
cargo test --lib --features gui,codex,kimi
cargo clippy --all-targets --features gui,codex,kimi
cargo check --features gui,kimi
cargo build --bin tanglewood-mcp --example kimi_smoke --features kimi
```

The Kimi-only check verifies feature independence. Run the no-default-features domain suite only if shared extraction changes those paths; existing baseline Clippy warnings do not require unrelated cleanup. A broad feature/device matrix is unnecessary. Run the harness metadata phase and the scoped `--live` phase once when authorized by the active implementation request; record real failures without substituting mocks. Build the GUI binary only as needed for the native check; do not add a release build.

Inspect the actual Linux window with both backends: a regular window and one compact pullout layout, backend/model/thinking popovers, a streamed Markdown/tool result, permission/Stop, keyboard focus/accessibility labels, and a retained draft across backend/session changes. Compare against the approved quiet design and verify Notes still edits/saves during agent failure. Reuse existing native preview infrastructure if helpful; a new screenshot suite is not required. No Android or network-isolation claim follows from host compilation.

Reviewer acceptance: real supported capabilities only; Codex semantics preserved; config responses authoritative; draft/history/provider isolation; permission and cancellation correlation; process cleanup; unchanged single-writer/revision/revocation boundary with concurrent-client routing and disconnect isolation; native visual evidence and accurately limited live evidence. Fix concrete findings through the same developer, then let the same reviewer assess the delta, stopping after four cycles at most. Stop repeating checks after passing evidence unless subsequent changes invalidate it. Root reports unresolved findings or unavailable live evidence explicitly and owns unsigned integration commits.
